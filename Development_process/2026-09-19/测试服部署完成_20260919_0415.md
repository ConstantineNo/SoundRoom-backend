## 常驻与运维

`/etc/systemd/system/soundroom-backend.service`：以soundroom用户运行，WorkingDirectory为shared，后端仅监听`127.0.0.1:18080`，单worker，Restart=always、RestartSec=3。数据库/文件在release外，启用systemd开机自启。

Nginx配置为`/etc/nginx/sites-available/soundroom-backend.conf`，绑定80，server_name为163.192.34.11；/api去前缀代理，根路径直接代理。客户端原始IP由Nginx设置，后端只信任127.0.0.1的转发头。原443/mihomo、PostgreSQL、Redis等服务不变。

```bash
sudo systemctl status soundroom-backend nginx
sudo systemctl is-enabled soundroom-backend nginx
sudo journalctl -u soundroom-backend -n 100 --no-pager
sudo systemctl restart soundroom-backend
curl -fsS http://127.0.0.1:18080/health
```

升级入口在后端代码仓`scripts/deployment/deploy_test.sh`。先检查目标状态，再生成白名单发布包并上传SHA256校验；长时间安装交由独立systemd部署任务，避免SSH断开中止。脚本迁移前备份已有数据库。不要只切换代码symlink就盲目回退跨数据迁移版本，需核对数据库兼容性或恢复经验证的备份。
