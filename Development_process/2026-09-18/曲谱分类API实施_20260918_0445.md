# 曲谱分类后端 API 实施与验证

日期：2026-09-18。依据共享文档库 `design_docs/CONTRACT/change2-score-management.md`、SCHEMA、FLOW 和笛调研究实施。修改保留在本地工作树，未部署、未迁移任何现有业务数据库；手机端联调与真实跟练能力未验收。

## 交付范围

- C01–C10：字典、候选、两级聚合、分类列表、无文件快速建档、详情、元信息更新、方案新增/替换/删除。
- S01–S03：主动公开、撤回、复制成自己的私有曲目。多方案、有序段、确认状态和来源标记保留；不复制候选凭据、个人练习资料或来源录音。
- A01–A03/A05：私有资料上传、授权下载、解绑、方案跟练状态查询。
- A04：提供预留的鉴权/归属/ETag/输入校验入口。现有解析器不能验证谱面位置与跟练目标，合法请求明确返回 `409 NOTATION_NOT_READY`；没有伪造可用绑定或 `available=true`。这是目标契约第8节尚未冻结的跨域部分，不代表跟练谱接入完成。

## 分层与数据库

路由位于 `app/api/endpoints/{scores,classification,score_assets,private_uploads}.py`；严格输入/输出 DTO 位于 `app/schemas/classification.py`；业务逻辑位于 `app/services/{classification,flute_candidates,score_assets}.py`；SQL 查询与事务入口位于 `app/crud/classification.py`。

`Score` 保留 id，新增 original_key、notes、visibility、revision；新增 score_arrangements、score_sections、score_assets、score_idempotency。默认私有，每曲恰有一套默认方案；段数组顺序持久化为从0开始的 position。只有 confirmed 的规范组合参与分类。局部组合在同一段匹配，全曲匹配必须在同一套 complete 方案中满足所有段；SQL `EXISTS` 过滤后才分页，聚合使用 `COUNT(DISTINCT score_id)`，不是段落数。列表按 updated_at DESC、id DESC。

依据 key_basis 追踪依赖：original_key 改动仅影响 original 段；local/performance 独立。影响依据的指法、所选调性和器型修改会把原确认值移至所有者可见证据，当前 flute_key 置空并标 needs_review。标题、标签不使分类失效。新增段默认 pending。

迁移脚本 `migrations/versions/c2a20260918_score_classification.py`：旧记录保留 id、所有者、图片/音频路径、ABC和派生JSON；以 song_key 回填 original_key，创建 unknown 范围的默认方案及“范围待核实”段，状态为 needs_review。无主条目保持私有且不可被任意登录用户接管。旧 flute_key 仅作为 evidence.previous_flute_key。旧字段保留用于迁移追溯，新写入不再维护第二份分类真相。旧图片/音频同时登记为独立私有附件，新详情可发现并经A02下载；迁移不读取或移动原文件。未核实文件类型时以application/octet-stream附件下载，size=null（未知），issues=LEGACY_CONTENT_UNVERIFIED；读取仍限于uploads目录内，禁止旧路径穿越。

迁移依赖上一版 `fe4213a38322`，已验证有数据升级及重复 upgrade 无副作用。禁止把多个方案自动压回标量，因此 downgrade 明确拒绝；回退需要经验证的迁移前备份。没有对当前业务数据库执行迁移。

## 并发、凭据与权限

现有数据库是 SQLite。写操作在读取聚合/幂等状态之前使用数据库 `BEGIN IMMEDIATE`，保护跨线程、跨进程的检查与写入；幂等表另有用户＋方法＋路径＋键唯一约束。方案、段、元信息、资产关联、可见性操作原子提交并更新聚合 ETag。

- `If-Match` 缺少428、陈旧412；详情和写入响应返回 ETag，CORS 显式 expose `ETag`。
- 创建曲目/方案/资料/副本要求 `Idempotency-Key`。相同请求重放原响应和原 ETag，不同请求409；重放前检查当前访问权，先重放再检查旧 If-Match。
- 候选采用 `dizi-key-pc-v1`。八类指法与十二音级字典，不将降7混作7、不把等音拼写分成两个分类。原调 D＋筒音作2候选 A；1=A 与6=A分别解释。仅给音级关系，不校验整曲音域。
- 候选凭据使用现有签名机制但独立 purpose，绑定用户、有效输入、规则及候选。认证拒绝将候选 token 当作 Bearer 登录凭据。
- manual 确认可覆盖候选，但错误规范值拒绝；关系不一致给 KEY_RELATION_MISMATCH，未知规则给 RELATION_NOT_CHECKED。
- 私有资源越权404，公开资源非所有者写403；不继承管理员代改/无主条目旁路。公开响应移除候选证据。曲目发布不授权附件公开。

配置：`CLASSIFICATION_CANDIDATE_TTL=900`秒，`CLASSIFICATION_IDEMPOTENCY_TTL=86400`秒。到期同键可创建新资源，不能依赖超过24小时的去重保证；到期记录按键访问时替换，当前未增加后台清理任务。

## 附件与旧入口

`CLASSIFICATION_ASSET_DIR` 默认 `private_score_assets`，`CLASSIFICATION_MAX_ASSET_SIZE` 默认20 MiB。类型按内容验证，不信任文件名或客户端 Content-Type：谱图 PNG/JPEG；参考音频单/双声道 PCM WAV；机器谱 UTF-8 ABC，须有 K: 行并关联本曲方案。ABC仅安全保存为 stored，issues=NOTATION_NOT_VERIFIED，不同步解析、生成跟练任务或承诺处理完成时限。其他格式415，空文件422，超限413。后续格式支持需另补验证。

文件使用服务端随机 storage_key；API不暴露磁盘路径。上传事务失败回滚数据库，已写文件移到存储目录的 recycle；解绑不物理删除。所有附件默认独立私有，现有客户端没有附件公开授权字段；public_allowed/copy_allowed 仅为独立授权预留，不由曲目 publish 自动设置。复制仅引用已经独立允许公开/复制的展示资料，副本重新私有，机器谱不继承可用跟练状态。

旧 `/uploads` 公共静态挂载已移除，改为基于现有曲目/录音所有者的鉴权读取；即使知道路径，匿名或他人也不能取得文件。播放列表返回受权限过滤的 ScoreSummary，原曲目撤回后其既有列表项只保留引用，score=null，不泄漏旧曲谱字段。录音/列表新增引用也检查曲目可见性。

客户端需协调切换：

1. `POST /scores/` 使用 JSON；旧 multipart 建档不保留。先建档，再 POST assets。
2. 后端路径不加 `/api`；开发代理加 `/api` 并移除前缀。集合路径保留尾斜杠，POST直接调用 `/scores/`。
3. 目标 JSON 响应统一 `{code:0,message:"ok",data:...}`；旧裸对象客户端需要适配。错误 code 为整数，reason 位于 detail，验证错误422。
4. 列表只接受 page/size；skip/limit 显式422，不静默忽略。
5. 旧 PUT 元信息及 ABC 同样需要所有者身份和 If-Match，返回统一 envelope。分类标量只能映射已核实的单方案单段；复杂/unknown范围返回 LEGACY_AMBIGUOUS。song_key 走依赖失效逻辑。
6. 旧 ABC 只允许单方案，先保存ABC再派生JSON，不因此宣称可跟练；多方案返回 LEGACY_AMBIGUOUS。
7. 曲目永久 DELETE 在契约外，入口鉴权后409 SCORE_DELETE_UNSUPPORTED，避免删除共享文件或成绩；可使用 unpublish 和方案删除。附件解绑、方案删除均不删实体文件。

## 可复现验证

从后端代码仓执行，测试临时文件全部位于工作区；为每次运行选择新的 basetemp：

```bash
python3.12 -m venv .venv
TMPDIR="$PWD/.runtime/classification/tmp" .venv/bin/python -m pip install -r requirements-test.txt
TMPDIR="$PWD/.runtime/classification/tmp" MPLCONFIGDIR="$PWD/.runtime/classification/mpl" \
  .venv/bin/python -m pytest classification_tests \
  --basetemp="$PWD/.runtime/classification/pytest-local" -q --disable-warnings
```

首次需先创建 `.runtime/classification/tmp`。部署升级命令为 `.venv/bin/python -m alembic upgrade head`，应在备份、明确 DATABASE_URL 后执行；现有 create_all 不会升级旧表，不能替代 Alembic。

59项测试覆盖 C01–C10、S01–S03、附件与预留绑定错误路径、字典/同音异名/调性解释、无文件建档、确认/过期/跨用户凭据、局部依赖失效、A→B→A、整曲/局部/方案范围、去重与分页、并发幂等/ETag、权限/静态旁路/播放列表撤回、旧PUT/ABC保护、文件回滚、旧数据迁移与 ORM schema drift。另以子进程启动完整 app、中间件、认证、已迁移数据库，检查 CORS、OpenAPI目标路由及 HTTP 行为。证据见同目录 `classification-tests.txt`。

测试环境存在现有 datetime.utcnow/SQLAlchemy declarative_base 及测试客户端弃用警告；未改变测试结果。旧 tests/ 中部分用例断言被本契约替换的 multipart/裸对象/skip-limit行为，不作为本次新契约验收集。识别算法代码未改动。

未验证：手机端登记/浏览/编辑流程、生产反向代理配置、真实历史数据归属盘点、真实器型/音域可演奏性、谱面定位/校对/跟练能力跨域接入。这里的本地HTTP/数据库通过不等于上述验收完成。
