本地软件里程碑已实现；真实竹笛/哼唱识别质量尚未验收。代码、CLI、GUI 与独立 HTTP harness 均调用 `app/services/audio_recognition`，不启动旧业务应用、不访问数据库。当前仅 pYIN，无模型权重下载；torchcrepe 同集对照等待真实授权标注集。

## 环境与启动

已验证：macOS arm64，Python 3.12.3。运行所有命令前进入 `SoundRoom-backend` 代码仓。主业务 `requirements.txt` 不混入 Qt；识别核心入口为 `requirements-recognition.txt`，GUI/测试入口为 `requirements-recognition-lab.txt`，完整实测依赖固定于 `requirements-recognition-lab.lock.txt`。

本机环境已经位于 `.venv-recognition`。重新安装可运行：

```sh
scripts/setup-recognition /Users/jumomo/.local/share/mise/installs/python/3.12.3/bin/python3.12
```

其他机器传入自己的 Python 3.12 可执行文件。只安装无 GUI 核心时，在仓内创建虚拟环境后，用完整 lock 作为 constraints：

```sh
mkdir -p .runtime/tmp .runtime/cache
export TMPDIR="$PWD/.runtime/tmp"
export PIP_CACHE_DIR="$PWD/.runtime/cache/pip"
python3.12 -m venv .venv-recognition
.venv-recognition/bin/python -m pip install -c requirements-recognition-lab.lock.txt -r requirements-recognition.txt
```

使用入口：

```sh
# 原生窗口；可在窗口内导入，或传入音频路径
scripts/recognition gui
scripts/recognition gui .runtime/synthetic-verified/fixtures/detuned_44100.wav

# JSON + 帧 CSV + 音符 CSV + 本次参数 JSON
scripts/recognition analyze input.wav --output .runtime/result.json
scripts/recognition analyze input.wav --params .runtime/result.params.json --output .runtime/rerun.json

# 独立测试入口；禁止直接跑旧 tests/ 或导入 app.main
scripts/recognition test -q

# 生成合成信号、标注、逐场景结果和报告
scripts/recognition evaluate --output .runtime/synthetic-new

# 用户授权提供的真实音频与离散音符标注
scripts/recognition evaluate --audio sample.wav --annotations annotations.json --output .runtime/real-evaluation

# 独立 localhost HTTP harness；不接生产主应用
scripts/recognition api
# 另一个终端中：
curl --data-binary @input.wav -H 'Content-Type: audio/wav' http://127.0.0.1:8011/recognize
```

API 用原始文件字节作为 body；可在 `params` query 传 JSON 配置。无认证，只用于本机验证；当前一个分析同时运行，忙时 429，body 超限 413，解码/参数错误 422。不会在 uploads 或业务库中落盘。生产接入、鉴权、手机容器/时钟仍在后续阶段。

## 操作流程

1. 点击「导入音频」，支持 WAV/FLAC/AIFF/OGG；最多60秒、32 MiB、1/2声道、8–192 kHz。不支持改扩展名伪装编码。立体声取算术平均，保留混合诊断。
2. 或点击「临时录制」，再点击「停止并使用录音」。默认系统输入设备，最多60秒。PCM 只驻留内存；停止失败、关闭或替换时释放，不创建录音文件。设备无权限/溢出会报错；全零采集显示检查权限与输入设备的提示。系统输入/输出设备在 macOS 系统设置中选择。
3. 点击「分析」。后台线程运行 pYIN；首次 JIT 会较慢。可同时查看、缩放与回放；分析中不更换输入，结束后可关闭。
4. 四张图共享秒时间轴：波形、频谱、F0/候选事件、发声概率/起音强度。滚轮缩放，拖动绿色选区或编辑起止秒数，双击定位起点，点击「缩放选区」或「全览」。频谱只作显示，用8 kHz显示重采样；分析仍用配置中的采样率。
5. 点击「播放选区」，可勾选循环。「停止回放」立即停止。回放保留原声道，由 Qt 原生播放器消费内存 WAV；选区首尾各5毫秒淡入淡出仅影响试听，不修改分析 PCM。光标是原生播放器报告的近似进度，不能作为精确起音标注。
6. 调参数后点击重新分析。青色当前 F0，橙色上次 F0，透明横带/竖线显示当前音符及边界；切换新音频清除旧结果。参数变更不会自动修改旧图，详情显示生成结果时的参数。
7. 选定起止时间并输入 Hz，点击「以选区添加标注」，可删除末条；紫色显示人工标注。导入/导出 JSON 标注，字段为 `start_seconds`, `end_seconds`, `frequency_hz`, `label`。标注必须落在当前音频范围内。
8. 「导出结果」输出 JSON、frames/notes CSV 和 params JSON，不复制音频；导出与导入标注独立。文件写入用户明确选择的位置。

标注示例：

```json
[{"start_seconds":0.2,"end_seconds":0.9,"frequency_hz":440.0,"label":"A4"}]
```

## 结果语义与算法边界

- `schema_version=1.0`；核心实现版本 `soundroom-pyin-segmentation-1.0`。
- audio 含原采样率/样本数/声道数、秒时长、峰值、削波比例和解码 PCM 摘要（不是源文件字节摘要）。
- 默认分析采样率22050 Hz、窗口2048、步长220（约9.977 ms）、音域65.406–2093.005 Hz；完整参数写入每次结果。窗口约92.9 ms，步长不代表边界精度保证。
- 第 i 帧中心时间 `i * hop / analysis_sample_rate`，以解码后音频第0样本为原点；`source_sample` 是原采样率下最接近的样本位置。音符起止为候选帧边界，不对齐节拍。
- `raw_f0_hz` 保留 pYIN 的 F0（其无声时为 null）；`engine_voiced` 与 `voiced_probability` 保留引擎输出。`f0_hz/voiced` 再经过可见的概率/能量门限，拒识用 null。发声概率不是音高正确率。
- 音符频率以已接收 F0 的对数中位数汇总；MIDI 浮点数、最近音名/音分是派生标签，不修正频率。短于 min_note_seconds 的事件不输出，但原帧仍保留。
- 分段结合发声边界、跨 pYIN 过渡窗口的稳定音高变化，以及能量低谷与频谱起音证据。所有边界标为 candidate；滑音/明显变音保留不确定标志。同音反复、连音、气声起音对真实演奏仍可能失败。
- 当前单声部；噪声/伴奏/复音不保证可用；越界音高可能折到错误八度，不能靠引擎保证检出。短片段/削波/低能量有诊断。
- CLI/GUI 比较 frames、notes、audio 与配置，耗时属于每次运行实测值，不应要求逐字相同。

## 隔离与证据

测试位于被 Git 跟踪的 `recognition_tests/`，通过 `--confcutdir` 与禁止业务模块导入的 finder 共同防止继承旧 autouse fixture。启动脚本禁用外部 pytest 插件自动加载。每次测试临时目录、Numba/下载缓存、虚拟环境、生成结果都在仓内；`.runtime` 与 `.venv-recognition` 已忽略。

实测完整结果见相邻 `识别验证证据_20260918_0240.md` 与 `recognition-evidence/`。默认选择 pYIN 的理由是无需权重、可 CPU 独立复现且通过本轮机制验证；不是依据真实音源对照选出的永久赢家。

第三方来源：依赖从 PyPI 获取，Qt/PySide6 使用其对应发行许可（LGPL/GPL/commercial），pyqtgraph 为 MIT，librosa 为 ISC，sounddevice 为 MIT。没有重打包或分发模型权重。API/算法参照 [pYIN 0.11.0 官方文档](https://librosa.org/doc/0.11.0/generated/librosa.pyin.html)、[sounddevice 0.5.3 官方流文档](https://python-sounddevice.readthedocs.io/en/0.5.3/api/streams.html)、[pyqtgraph 官方文档](https://pyqtgraph.readthedocs.io/en/latest/api_reference/graphicsItems/plotitem.html)。完整第三方许可随安装包保留。
